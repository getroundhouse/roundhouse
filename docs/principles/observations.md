# Observations

These rules cover observations, the hub's copies of what others own: what one is, what it holds, and how fresh it says it is. `docs/principles/keeping-observations.md` says where one comes from, including how what an agent says a part at a time is merged rather than replacing the whole, where the hub keeps it and how a client keeps its copy. `docs/principles/serving.md` says what else a hub serves and what the hub keeps current, and `docs/principles/outside-systems.md` how the hub reads GitHub.

## What an observation is

- **An observation is the hub's copy of state someone else owns, as the hub last observed it.** Git, GitHub and an agent each own state the hub only observes: by watching it, by asking for it, or by being told as it changes. Where the hub can ask again, it does, to keep its copy current. Where it can't, as with what only a running agent says, its copy is as of when that was last said. What an agent says in an event is the log's, so what the hub works out from it is a record, such as a session's status and what its running agent claims. The hub also sets a run's claims outside any event, as a worker answers a launch and as the hub connects again to a worker an earlier hub left, but only to repair the record of a run it finds running whose claims the record lacks, so the claims stay a record. *Not built:* such a copy is a record or a field of one, as are a workspace's branches, whether the default GitHub account can push to a repository, and how many files a workspace has uncommitted. Or it isn't kept, as a workspace's diff is read whole where its hub keeps no current summary of its changed files.
- **What the hub reads from an outside system is a cache, and what Roundhouse decides about it is the hub's own record, which keeps only the link.** Which pull request is a workspace's, and which account a project uses, are Roundhouse's decisions, so they're records and the truth. A workspace's record keeps its pull request's address, and what GitHub says of the pull request is in the cache. What's read from GitHub can be read again, so losing it loses nothing. A record can't always be rebuilt: once a workspace's branch is deleted, or its name is used again, GitHub alone can't say which pull request the workspace had.
- **An observation says how fresh it is: not known, current, or as of a time.** It's current while something keeps it up to date, and otherwise as it was last read, with when. So no client shows an old reading as current, or takes "not known" for "none". Each read replaces it whole, and its revision moves only when what it says changes, so reading the same again sends clients nothing.

  ```rust
  // crates/protocol/src/model/observation/observed.rs, abridged
  pub enum Observed<T> {
      /// Never read, or emptied since.
      NotKnown,
      /// Kept up to date now, as what a client follows is.
      Current { value: T },
      /// As it was last read, at `as_of_ms`, since nothing keeps it up to date now.
      AsOf { value: T, as_of_ms: i64 },
  }
  ```
- **An observation holds the whole of what it's of, unless that's too big for every client that follows it to hold.** Only then is it split: the observation holds a summary, and the detail is read on request from whoever owns it, a worker or GitHub, in pages past a size, and the hub keeps none of it. The summary names a version of each piece of detail, so a client showing the detail reads it again only when its version changes. For example, an agent's list of models is an observation whole. A workspace's changed files, each with its lines added and removed, are a summary, and one file's diff is read on request.
- **What the API's cache holds of a chat's conversation is sent at the hub's level with one bit of the chat's context: whether it's big enough that writing it into the cache again costs something.** So a sidebar draws every chat's cache from the hub's level, and is told nothing as a context moves within one side of that. It changes as the chat's record was told when it was a field of it: at a request made while the agent isn't working, as a turn ends, and as something empties the cache, and not on every request. *Unconfirmed.*
- **A workspace's summary of its changes names at most 5,000 files, those git tracks first and then the untracked ones, each in order of their paths, and says how many it leaves out, with its totals over all of them.** So an unignored folder of 300,000 files neither sends every client that follows the workspace 45 MB on each change, nor crowds out the agent's ten edits. A client lists none of the files past the 5,000, and says how many there are.
- **How the hub's own asking for an observation stands is a record kept in memory, apart from the observation.** For example, whether the hub is asking an agent which models it offers is the list of models' record, as an update a person asked for is apart from the release the feed offers. What the cache file kept of what an agent offers serves the hub's checks at once after it starts again, while the agent is asked again where that's due. *Unconfirmed.*
- **A value the hub works out from other state is an observation if any of that state is one,** and the hub works it out again when any of it changes. For example, how a workspace's pull request stands is worked out from the workspace's record and from what GitHub says, so it's an observation.
