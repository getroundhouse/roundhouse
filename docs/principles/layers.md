# Crates and layers

These rules say which crate can depend on which, how code is layered inside the hub and the worker, and how an error crosses the layers. `tools/policy` checks most of the rules about crates against the real dependency graph, so `cargo test` fails when a new dependency breaks one. `docs/standards/rust.md` has the rules that apply to every crate and module.

- **`protocol` does no IO and has no UI.** Every crate depends on it, so it has to stay small and stable.
- **`terminal-state` does no IO and has no UI.** The worker and `client-core` both build it, and each gets a terminal's bytes its own way.
- **`hub` and `worker` don't depend on each other, and `hub` doesn't depend on `agents`.** A hub and a worker talk only over the worker protocol, so a worker on another machine changes only the transport. Only `apps/daemon` builds both, since `roundhoused` runs as either.
- **No client depends on `hub`, `github`, `worker`, `agents` or `providers`.** A client reaches a hub only through `protocol`, so the compiler enforces that clients talk only to hubs, as `docs/principles/parts.md` says.
- **GPUI stays in `transcript`, `dictation-ui`, `terminal-view`, `look` and `apps/`.** Nothing under `hub`, `github`, `worker`, `agents` or `providers` depends on GPUI or gpui-kit, so the hub and the worker build on Linux without it.
- **`client-core` uses no GPUI and no async runtime.** It's built from blocking calls and channels. That keeps GPUI's executor out of it, and a native mobile client stays possible if GPUI doesn't work out on mobile.
- **`client-core` and the iPhone app start no process.** Every client builds `client-core`, and a phone never starts a hub. So starting a hub on this machine is in `local-hub`, which only the desktop app and the CLI build. Neither `client-core` nor the iPhone app depends on `local-hub`, `process` or `private-files`.
- **`dictation`, `phonon`, `models`, `sound`, `fetching` and `now-playing` use no UI, no async runtime and none of the workspace's other crates but each other.** So any client on any device can use them, such as the iPhone app. `dictation` depends only on `models`, for its model's files, and on `sound`, for the microphone and quieting what's playing. `phonon`, the engine that speaks, depends only on `models`, and knows nothing of the speakers. `models` depends only on `fetching`, with its `download` feature, to download a model, and `sound` only on `now-playing`, to pause what's playing. *Unconfirmed.*
- **Logic that every client needs is in `client-core`, and a view only draws it and passes input on.** Then the CLI, the desktop app and a mobile app behave the same without each implementing the logic. For example, `client-core`'s `Approval` says what an approval request asks and builds the `Decision` that answers it. `client-core` also words, for a person, what it means when the hub didn't do what was asked.
- **Dependencies point inward: handlers call operations, and operations call stores and integrations.** A handler, in `hub::server` or `worker::serve`, parses a request, calls one operation and maps its result. An operation holds the logic, in one module per area. The store, `hub::store`, holds all the SQL. An integration talks to one outside system, as `docs/principles/outside-systems.md` says. A layer returns a lower layer's type where it means the same thing, instead of copying it.
- **Hub and worker operations return `protocol::client::ApiError`, the error both protocols carry.** Its `ErrorCode` is a closed set of meanings, such as `NotFound` and `Conflict`, and not a set of transport statuses, so a second enum that mapped onto it would only be a copy. Callers and tests match `code`, and `message` is for people. A condition that callers must tell apart gets a new `ErrorCode`.
- **Each crate converts lower errors to `ApiError` in one place, an `impl From<…> for ApiError`.** The mapping then reads as one table, and that place logs `Internal` failures with their source. A lower layer keeps an error type of its own when `ApiError` would lose the cause. `hub::store` has its own enum, because `ApiError` holds only text and would discard the SQLite error.
