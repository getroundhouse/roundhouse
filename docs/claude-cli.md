# Driving the Claude CLI

How the worker runs the `claude` CLI, and how the CLI behaves.

The worker drives the CLI directly from Rust, without an SDK sidecar. It runs the user's installed `claude`, so there's nothing to redistribute, and it picks up their login and settings. The price is that a CLI upgrade can break the adapter, which the captured fixtures and contract tests are there to catch.

**Why.** The Agent SDK spawns this same CLI and talks to it over the same stdio protocol, as its flag list and `sdk.d.ts` show (read from `@anthropic-ai/claude-agent-sdk` 0.3.319, which isn't vendored here). Prompts, streaming, approvals, interrupts and resuming all work directly, with no JavaScript runtime to ship. Other features, such as `rewind_files` and hook callbacks, are control messages on the same stream, as `set_model` and `set_permission_mode` are. The SDK's in-process MCP servers are reached through control messages on the same stream too, and nothing here declares one.

**The main risk.** The control protocol is described by the SDK's types rather than the CLI's documentation. `crates/agents/tests/claude/contract.rs` checks the adapter against captured real output, and `controls.rs` beside it against the CLI's answers to control requests. Rerunning `tools/smoke/capture_claude_fixture.py` after a CLI upgrade shows what changed.

All of the following was observed on CLI 2.1.319 with Haiku, except where a row says otherwise:

| Interrupt with prompts waiting | With `cancel_queued`, a prompt that hadn't `started` gets `cancelled` before the turn's `result`, and the prompts it had taken get `cancelled` after. That line is the first to say either, so the adapter records the list again, with them now known: in the line's place for a monitor, and straight after it, with no raw line of its own, for a subagent, whose line is its `SubagentStarted`. It forgets a task's call once a list that held it leaves it out, or when it ends without having been listed. `init` counts as running, since it's the only sign of a turn the CLI starts by itself |
